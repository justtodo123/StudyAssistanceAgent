# 多轮工具编排学习助手

## 描述

这是本项目的**核心面试演示技能**，展示 Agent 多轮工具编排能力：一次学习会话中串联 4 个工具（QA 检索 → 知识讲解 → 出题测验 → 评估掌握度 → 记录复习），实现「问→查→学→练→评」闭环。

## 面试价值

此技能直接映射面试考点「**多轮工具调用 / Tool Orchestration**」：
- **工具选择**：根据用户意图动态选择调用哪个 API
- **上下文传递**：前一步的结果（检索到的知识）作为后一步的输入（出题依据）
- **编排逻辑**：顺序执行 + 条件分支（答对/答错不同路径）
- **状态管理**：跨步骤维护学习上下文

## 触发条件

- 用户说「帮我学一个知识点」「学一下 XX」「交互式学习」
- 用户说「讲讲进程同步然后考考我」「边学边练」
- 用户要求「完整的学习流程」「端到端学习」

## 不触发条件

- 用户只想问一个问题（用 QA）
- 用户只想做题（用 quiz-generator）
- 用户想安排学习计划（用 review-plan）

## 指令

### 整体流程

```
用户提出学习主题
    │
    ▼
┌─ 步骤 1：QA 检索 ─────────────────────┐
│  调用 POST /api/v1/qa                  │
│  获取知识条目 + 来源                    │
└────────────────────────────────────────┘
    │
    ▼
┌─ 步骤 2：知识讲解 ─────────────────────┐
│  结构化呈现检索结果                      │
│  标注来源、提炼核心要点                  │
└────────────────────────────────────────┘
    │
    ▼
┌─ 步骤 3：出题测验 ─────────────────────┐
│  调用 POST /api/v1/quiz                │
│  生成相关题目（优先 example 题型）       │
└────────────────────────────────────────┘
    │
    ▼
┌─ 步骤 4：等待用户作答 ──────────────────┐
│  呈现题目，等待用户回答                  │
└────────────────────────────────────────┘
    │
    ▼
┌─ 步骤 5：评估掌握度 ────────────────────┐
│  对比参考答案 / 检索相关知识验证          │
│  给出评分 + 具体反馈                     │
└────────────────────────────────────────┘
    │
    ├── 答对 → 步骤 6a：记录掌握
    └── 答错 → 步骤 6b：补充讲解 → 回到步骤 3
    │
    ▼
┌─ 步骤 6：记录复习 ─────────────────────┐
│  调用 POST /api/v1/review-log          │
│  更新间隔重复排程                       │
└────────────────────────────────────────┘
    │
    ▼
  学习完成，展示总结
```

### 步骤 1：QA 检索

向用户确认学习主题后，调用 QA 端点：

```json
POST /api/v1/qa
{
  "question": "{用户的学习主题}",
  "course": "{课程简称}",
  "top_k": 3,
  "use_llm": false
}
```

获取检索结果（sources）和摘要回答（answer）。

### 步骤 2：知识讲解

基于检索结果，结构化呈现：

```markdown
## 📖 {主题}

> 来源：{source_file_1}、{source_file_2}

### 核心概念
{从检索结果中提炼的要点}

### 关键原理
{提取核心算法/机制/对比}

### 易错点
{从条目中提取的高频考点}
```

**要求**：讲解控制在 200 字以内，突出重点，不照搬原文。

### 步骤 3：出题测验

调用 quiz 端点生成与主题相关的题目：

```json
POST /api/v1/quiz
{
  "course": "{课程}",
  "count": 2,
  "topics": ["{主题关键词}"]
}
```

优先选择 `example` 题型（有完整参考答案）。如果该主题无 example 题，使用 concept 题型。

### 步骤 4：交互答题

- 一次呈现一道题（不显示答案）
- 等待用户作答
- 用户可以跳过（标记为「不确定」）

### 步骤 5：评估掌握度

根据题型不同评估方式：

**example 题型**（有标准答案）：
- 对比用户答案与参考答案的关键要素
- 评分：完全正确 / 部分正确 / 错误
- 给出具体差异说明

**concept/retrieval 题型**（无标准答案）：
- 调用 QA 端点验证用户答案中的关键点
- 评分：理解到位 / 有偏差 / 需要补充
- 给出正确要点

```markdown
### 📝 评估

**你的回答**：{用户答案要点}

**参考要点**：{标准答案/关键知识点}

**评分**：{⭐⭐⭐ 完全正确 / ⭐⭐ 部分正确 / ⭐ 需要复习}

**反馈**：{具体的改进建议}
```

### 步骤 6a：答对路径

```markdown
✅ 掌握良好！已记录复习。

**学习总结**：
- 主题：{主题}
- 掌握度：{评分}
- 下次复习：{根据间隔重复计算}
```

调用 review-log 记录：
```json
POST /api/v1/review-log
{
  "file": "{来源文件}",
  "course": "{课程}"
}
```

### 步骤 6b：答错路径

```markdown
💡 这个点还需要加强，我再给你讲解一下：

{针对错误点的补充讲解}

再做一道题巩固一下？
```

- 补充讲解后回到步骤 3 再出一道题
- 如果连续 2 次答错，给出完整讲解并建议复习该条目

### 步骤 7：学习总结

```markdown
## 📊 学习总结

**主题**：{主题}
**涉及条目**：{条目列表}
**测验得分**：{正确数}/{总题数}
**掌握度**：{高/中/低}
**建议**：{下一步学习建议}

### 工具调用链
1. QA 检索 → 获取 {N} 条知识片段
2. 知识讲解 → 提炼核心要点
3. 出题测验 → {M} 道题
4. 掌握度评估 → {评分}
5. 复习记录 → 下次 {date}
```

最后的「工具调用链」部分是**面试演示重点**，展示 Agent 的编排能力。

## 行为准则

**应该做**：
- 每一步都明确告诉用户当前在做什么（步骤标注）
- 讲解要精炼，突出重点，不要照搬原文
- 评估要客观，答错时给出建设性反馈
- 最后的「工具调用链」总结是面试亮点，务必展示

**不应该做**：
- 不要跳过任何步骤（完整展示编排流程）
- 不要在用户没回答时就给出答案
- 不要一次出太多题（1-2 题即可，重点是流程演示）

## 成功标准

- [ ] 完整走完 QA → 讲解 → 出题 → 作答 → 评估 → 记录 六步
- [ ] 每步都有明确的工具调用（API 调用）
- [ ] 上下文正确传递（检索结果影响出题，出题影响评估）
- [ ] 最后展示「工具调用链」总结
- [ ] 答对/答错有不同分支路径

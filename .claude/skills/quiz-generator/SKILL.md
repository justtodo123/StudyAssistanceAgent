# 测验生成技能

## 描述

从课程知识库自动生成测验题目。支持三种题型：经典例题（含参考答案）、检索题（评测集，需查阅知识条目）、概念题（从标签模板生成）。

## 触发条件

- 用户说「出几道题」「帮我出题」「做练习」「生成测验」「自测一下」
- 用户提到某门课程 + 想做题
- 用户要求「随堂测试」「课后练习」

## 不触发条件

- 用户只是问某个知识点（用 QA）
- 用户要求生成学习计划（用 review-plan）
- 用户要求查看学习进度（用 review-due）

## 指令

### 步骤 1：收集信息

向用户确认以下信息（若未提供则使用默认值）：

| 参数 | 说明 | 默认值 |
|---|---|---|
| `course` | 课程简称 | **必填**，提示可选 os / ds / co |
| `count` | 题目数量 | 5（范围 1-20） |
| `difficulty` | 难度筛选 | 不筛选（混合出题） |
| `topics` | 标签筛选 | 不筛选（混合出题） |

### 步骤 2：生成测验

调用 `QuizService.generate(req)` 从三个数据源收集题目：

1. **经典例题**（type=example）：从 `knowledge/{course}/` 各条目的 `## 经典例题` 段落提取 `**题干**/**解答**` 对，含完整参考答案
2. **检索题**（type=retrieval）：从 `tools/evaluations/{course}.json` 加载评测集问题，无答案，需查阅知识条目验证
3. **概念题**（type=concept）：从知识条目的 tags 生成 "什么是 X？" 型问题

按难度和标签筛选后随机采样 `count` 题。

### 步骤 3：呈现测验

以清晰的格式呈现题目：

```markdown
## 测验：{course}（{count} 题）

### 第 1 题 [example]
**题目**：{question}
<details><summary>查看答案</summary>
{answer}
</details>
> 来源：[{source_title}]({source_file})

### 第 2 题 [retrieval]
**题目**：{question}
> 💡 请查阅 [{source_file}] 验证你的答案

### 第 3 题 [concept]
**题目**：{question}
> 💡 参考 [{source_file}] 中的相关内容
```

### 步骤 4：交互式答题（可选）

如果用户希望逐题作答：
1. 一次呈现一道题（不显示答案）
2. 等待用户回答
3. 对比参考答案（example 题型）或给出提示
4. 继续下一题
5. 最后汇总得分

### 步骤 5：汇总

呈现测验概览：
- 题目总数、题型分布
- 如果是交互式模式，显示正确率
- 建议复习哪些薄弱知识点

## 行为准则

**应该做**：
- 优先出经典例题（有完整答案，学习价值最高）
- 标注每道题的来源文件，方便用户深入查阅
- 交互式模式下对用户的回答给出建设性反馈
- 概念题和检索题鼓励用户自行查阅知识条目

**不应该做**：
- 不要编造题目答案（example 用原答案，其他引导查阅）
- 不要一次出太多题（建议 5-10 题一轮）
- 不要修改知识库条目内容

## 成功标准

- [ ] 题目来自知识库（非凭空编造）
- [ ] example 题型有完整参考答案
- [ ] 每道题标注来源文件
- [ ] 题型分布合理（三种类型都有机会出现）

## 一句话概括

查找是在数据集合中定位关键字等于给定值的元素。静态查找用顺序 / 折半 / 分块；动态查找用 BST / AVL / B 树；哈希表通过关键字直接映射地址，核心问题是冲突处理。折半判定树、BST 删除、AVL 旋转、哈希 ASL 计算是高频考题。

## 核心概念

### 线性表查找

| 方法 | 条件 | ASL | 复杂度 |
| --- | --- | --- | --- |
| 顺序查找 | 无要求 | (n+1)/2 | O(n) |
| 折半查找 | **有序 + 顺序存储** | ≈ log₂(n+1)-1 | O(log n) |
| 分块查找 | 块间有序、块内无序 | 介于二者之间 | O(√n) 量级 |

- **哨兵**：`R[0]` 存放待查 key，循环免去下标越界判断（顺序查找优化）
- **折半判定树**：折半查找过程等价于判定树中从根到某结点的路径；查找失败对应叶子结点的空孩子；最大比较次数 = 树高 = ⌊log₂n⌋ + 1

```c
// 折半查找
int Search_Bin(SSTable ST, KeyType key) {
    int low = 1, high = ST.length;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (key == ST.R[mid].key) return mid;
        else if (key < ST.R[mid].key) high = mid - 1;
        else low = mid + 1;
    }
    return 0;  // 查找失败
}
```

### 二叉排序树（BST）

- 定义：左子树所有值 < 根 < 右子树所有值（递归定义）
- **中序遍历 BST 得有序序列**
- 查找 / 插入：从根开始，key 小往左走、大往右走，走到空则失败（插入时在空位挂新叶子）
- **删除**（高频考点，三种情况）：
  1. 叶子：直接删除
  2. 只有左或右子树：用子树替代
  3. 左右子树都有：用**中序前驱**（左子树最右）或**中序后继**（右子树最左）替代，再删那个结点

### 平衡二叉树（AVL 树）

- 任意结点左右子树高度差 ≤ 1（平衡因子 BF = 左高 - 右高 ∈ {-1,0,1}）
- 查找时间复杂度 O(log n)（树高与 log₂n 同级）

**四种旋转**（插入导致失衡时）：

| 失衡类型 | 旋转方式 | 场景 |
| --- | --- | --- |
| LL | 右旋 | 在左子树的左孩子插入 |
| RR | 左旋 | 在右子树的右孩子插入 |
| LR | 先左旋再右旋 | 在左子树的右孩子插入 |
| RL | 先右旋再左旋 | 在右子树的左孩子插入 |

> 最小不平衡子树：离插入结点最近、BF 绝对值 > 1 的结点为根的子树。旋转针对该子树进行。

### B 树与 B+ 树（了解级）

- **m 阶 B 树**：每个结点最多 m 棵子树、至少 ⌈m/2⌉ 棵；所有叶子在同一层
- **B+ 树**：叶子结点包含所有关键字并串联成有序链表，适合范围查询；非叶子结点仅作索引
- B+ 树与 B 树区别：B+ 树叶子才存数据，非叶子只存索引；叶子有链表串联

### 哈希表（散列表）

**核心思想**：通过 `H(key)` 直接计算存储地址，理想 O(1) 查找。

**构造方法**：除留余数法最常用 —— `H(key) = key % p`（p 取小于表长的最大质数）。

**冲突处理**：

| 方法 | 原理 | 特点 |
| --- | --- | --- |
| 线性探测 | di = 1,2,3,... 逐个后移找空位 | 简单，但有「二次聚集」 |
| 二次探测 | di = ±1², ±2², ±3²,... | 减少聚集，但不保证找到空位 |
| 链地址法 | 同义词挂同一条链表 | 无聚集，实现简单，最常用 |

**装填因子** α = 填入记录数 / 表长，α 越大冲突越频繁。

**ASL 计算**（高频考题）：

- 线性探测：对每个关键字计算从 H(key) 到实际存放位置的比较次数，求平均
- 链地址法：ASL = Σ(每个同义词链上的比较次数) / 记录总数

## 易错点 / 高频考点

- [ ] 折半查找**仅适用于顺序存储的有序表**，不能用于链表（无法随机访问 mid）
- [ ] BST 删除第三种情况（左右子树都有）：找前驱或后继替代，**不是**直接删根
- [ ] AVL 旋转时要更新 BF，LR / RL 是双旋（先子树旋转再整树旋转）
- [ ] 哈希表查找效率取决于 α，与表大小和记录总数的比值有关，不是绝对大小
- [ ] 线性探测的查找成功 ASL 与查找失败 ASL 计算方式不同（失败需探测到空位为止）

## 经典例题

### 例题：哈希表线性探测 ASL 计算

**题干**：关键字 {19,14,23,01,68,20,84,27,55,11,10,79}，表长 m=16，H(key)=key%13，线性探测。求查找成功的 ASL。
**解答**：
1. 逐个计算 H(key) 并线性探测存放：19%13=6, 14%13=1, 23%13=10, 1%13=1→冲突→2, ...
2. 记录每个关键字的比较次数（从 H(key) 到实际位置的距离 + 1）
3. ASL = 比较次数总和 / 12

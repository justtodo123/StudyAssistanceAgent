## 一句话概括

内存管理解决三件事：**地址映射**（逻辑→物理）、**内存分配**（连续/分页/分段）、**扩充容量**（虚拟存储 + 页面置换）。考试重头戏是地址转换计算与置换算法比较。

## 核心概念

### 连续分配 vs 分页 vs 分段

| 方案 | 单位 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 连续分配 | 整个进程 | 简单 | 外部碎片、大小受限、内存利用率低 |
| 分页 | 固定大小页框/page | 无外部碎片、利于虚拟内存 | 有内部碎片（页内）、逻辑地址不连贯（对用户透明） |
| 分段 | 可变大小段 | 符合程序逻辑（代码/数据/栈分开放）、便于共享 | 有外部碎片、需特殊管理 |

**分页地址转换**
- 逻辑地址 = 页号 `P` + 页内偏移 `d`
- 页表：页号 → 页框号
- 物理地址 = 页框号 × 页大小 + `d`

**易错**：地址位数与页大小换算。例如逻辑地址 32 位、页大小 4KB（2^12），则页号占 20 位，共有 2^20 页。页表项数 = 页数。

### 页表优化（应对大页表的代价）

- **多级页表**：按需为实际使用的页分配页表，减少内存
- **快表 TLB**：页表项缓存，命中则免查内存（命中率 ~90%+）。先查 TLB，未命中再访页表
- 缺页中断时也可能装入 TLB

### 虚拟存储：请求分页 + 页面置换

- 只装入当前需要的页（请求分页），缺页时产生**缺页中断** → 调页入内存
- 缺页率 = 缺页次数 / 总访问次数（考试计算）
- **抖动 Thrashing**：进程频繁缺页，系统忙于换入换出 → 需降低多道程序度 / 用工作集控制

### 页面置换算法（必考）

| 算法 | 思想 | 优劣 |
| --- | --- | --- |
| OPT 最优 | 淘汰将来最久不使用 | 理论最优，无法实现（作基准） |
| FIFO | 淘汰最先进入 | 简单；有 **Belady 异例**（增加页框反而缺页增多） |
| LRU 最近最久未使用 | 淘汰最久未访问 | 性能好；需硬件支持（计数器/栈），实现贵 |
| CLOCK 时钟 | FIFO 上的改进：访问位轮询，遇 0 淘汰 | 近似 LRU，性价比高 |

- **Belady 异例**：仅 FIFO 可能发生（页框增多，缺页率不降反升）；LRU/OPT 满足**栈式特性**不会
- 缺页率计算的要点：LRU 看「最近访问时间」，FIFO 看「进入时间」，别混淆

## 经典例题

**题干**：页大小 4KB，逻辑地址 0x3F2A（16 进制），页表第 3 项 → 页框号 7。求物理地址。
**解答**：页内偏移 = 0x3F2A & 0xFFF = 0xF2A = 3882；物理地址 = 7 × 4096 + 3882 = 28672 + 3882 = 32554 = 0x7F2A。

## 易错点 / 高频考点

- [ ] 分页有**内部**碎片（一页内用不满），分段有**外部**碎片——高频设错点
- [ ] TLB 是「地址转换缓存」，与 Cache（数据缓存）不同：TLB 命中后仍需访内存取数
- [ ] Belady 异例只发生在 **FIFO**（某些页框数下）
- [ ] 缺页率计算注意访问序列是否含重复访问（重复命中不算缺页）

## 一句话概括

虚拟内存让程序以为自己独占连续大内存，实际只有活跃部分在物理内存中，其余在磁盘上按需换入。理解缺页处理、页面置换的深层机制和抖动控制是掌握内存管理的关键。

## 核心概念

### 请求分页 (Demand Paging)

- **思想**：程序开始时不装入任何页，运行中缺页时再调入（惰性加载）
- 页表项增加标志位：有效/无效位（该页是否在内存）、修改位、访问位
- **缺页中断处理流程**（高频）：
  1. 检查页表有效位 → 无效，产生缺页中断（陷阱）
  2. OS 查找空闲页框；若无，执行**页面置换**选一个牺牲页
  3. 若牺牲页被修改过 → 写回磁盘交换区；否则直接覆盖
  4. 从磁盘调入所需页到空闲页框
  5. 更新页表（有效位=1）→ 重新执行导致缺页的指令

### 写时复制 (Copy-on-Write, COW)

- fork() 后父子进程**共享**同一物理页框，均设为**只读**
- 任一方尝试**写** → 触发页保护异常 → OS 复制该页 → 双方均可写
- **意义**：避免 fork+exec 时的不必要全量内存复制（典型：shell 执行命令）
- Linux fork 就是 COW 实现的

### 页面分配策略

| 策略 | 说明 | 特点 |
| --- | --- | --- |
| **固定分配** | 进程页框数恒定 | 简单，但不灵活 |
| **可变分配** | 缺页率 → 动态调整页框数 | 适应负载变化 |
| **局部置换** | 缺页时只从本进程页框中置换 | 进程间隔离好 |
| **全局置换** | 缺页时可置换任意进程的页框 | 灵活但一个进程可能被挤出 |

> 经典组合：固定+局部（简单）、可变+局部（按工作集动态调整）、可变+全局（最灵活但有竞态风险）

### 工作集模型 (Working Set)

- **工作集**：进程在**最近 Δ 次访存**中访问的页集合 W(t, Δ)
- 有效工作集窗口 Δ ≈ 缺页率曲线拐点处
- **若分配给进程的页框 < 工作集大小 → 频繁缺页 → 系统抖动**
- 实用：OS 周期性检查进程工作集并调整页框分配

### 抖动 (Thrashing) 与防治

- **现象**：进程频繁缺页，大量时间花在换页而非执行上，CPU 利用率骤降
- **原因**：多道程序度过高，每个进程分到的页框小于其工作集
- **应对**：
  1. 降低多道程序度，暂停部分进程
  2. 增加内存 / 升级到更大容量
  3. **Page Fault Frequency (PFF)** 算法：缺页率高 → 增大页框分配；低 → 可适当回收

### 内存映射文件 (Memory-Mapped Files)

- 将文件区域映射到进程虚拟地址空间 → 访问内存即读写文件
- 读：文件→虚拟内存映射→按需缺页调入；写：修改页→脏页写回文件
- 用途：进程间共享内存（映射同一个文件）、高效 I/O

## 易错点 / 高频考点

- [ ] 缺页中断属于**可恢复异常**（不是错误），中断处理后重新执行原指令
- [ ] COW 中的「写」触发的是**页保护异常**（写只读页），不是缺页中断
- [ ] 局部置换不能从别的进程夺页框——这是防止抖动的重要保证
- [ ] 有效访问时间 EAT = (1-p)×内存访问 + p×缺页处理；p 是缺页率

## 经典例题

**题干**：某系统内存访问 100ns，缺页处理 25ms（含换入换出），缺页率 p=0.1%。求有效访问时间。
**解答**：EAT = (1−0.001)×100ns + 0.001×25×10^6ns = 99.9 + 25000 = 25099.9ns ≈ 25μs。即缺页率 0.1% 时，EAT 已是纯内存访问的 250 倍——缺页率必须极低。

## 一句话概括

一组进程互相等待对方占有的资源且永远不释放 → 死锁。防治四条路：**预防**（破坏必要条件）、**避免**（安全序列/银行家）、**检测与解除**（死锁定理）。

## 核心概念

### 死锁产生的四个必要条件（缺一不可）

1. **互斥**：资源一次只能一个进程用
2. **占有且等待**：进程持有资源又等待新资源
3. **不可剥夺**：已占有资源不能被强行夺走
4. **循环等待**：存在进程等待环路（A 等 B，B 等 C，C 等 A）

> 判断是否可能死锁，先检查这四点是否同时满足。

### 死锁预防（破坏一个条件）

| 条件 | 破坏方法 | 代价 |
| --- | --- | --- |
| 互斥 | 资源共享（如只读文件可共享） | 并非所有资源可共享 |
| 占有且等待 | 一次性申请全部资源 / 申请不到释放已有 | **资源利用率低**，可能饥饿 |
| 不可剥夺 | 占有资源可被抢占 | 实现复杂，进程易丢失进度 |
| 循环等待 | 全序分配（资源编号，按序申请） | 可能造成资源浪费 |

### 死锁避免：银行家算法（重点）

**基本概念**
- Available：可用资源向量
- Max：各进程最大需求
- Allocation：已分配
- Need = Max - Allocation
- **安全状态**：存在一个进程执行序列（安全序列），使得每个进程的 Need 都能被当前 Available 满足

**算法过程（安全性检查）**
1. 找进程 `Pi`：Finish[i]=false 且 `Need[i] <= Work`（Work 初始 = Available）
2. 若找到：`Work += Allocation[i]; Finish[i]=true`，回到 1
3. 若全部 Finish 为 true → 安全；否则 → 不安全，拒绝本次分配

**请求检查**：请求`Request[i] <= Need` 且 `<= Available`，预分配，安全则正式分配，否则回滚等待。

### 死锁检测与解除

- **资源分配图**：可简化为等待图；存在**环** ⟺ 存在死锁（单个资源实例时等价）
- 解除：撤销进程、剥夺资源、回退

## 易错点 / 高频考点

- [ ] 「银行家算法能预防死锁」错，是**避免**；防止/避免给的是不同层面的答案
- [ ] 计算安全性检查时 `Work` 会**累加**（已分配的资源回收），不是恒等于 Available
- [ ] Need 矩阵不动；变化的是 Work / Allocation（分配后要更新）
- [ ] 多资源实例下「资源分配图有环」不必然死锁；单资源实例才是充要

## 经典例题（考试必考计算）

**题干**：系统有 12 台磁带机。进程 P1..P4 的最大需求(Max)分别 5/4/6/4，已分配(Allocation) 4/1/2/2。求 Need 与 Available，并判是否安全（给出安全序列）。
**解答**：
```
Need = Max - Allocation = [1,3,4,2]
Available = 12 - (4+1+2+2) = 3
检查安全：Work=3
 - P1 Need[1]<=3 → Work=3+4=7, Finish[P1]=true
 - P2 Need[3]<=7 → Work=7+1=8
 - P3 Need[4]<=8 → Work=8+2=10
 - P4 Need[2]<=10 → Work=10+2=12
⇒ 安全序列 <P1,P2,P3,P4>，系统处于安全状态
```

## 一句话概括

段页式 = 分段（按程序逻辑分）+ 分页（按物理存储分），取各自之长：分段让程序逻辑清晰、便于共享保护，分页消除外部碎片、利于虚拟存储。

## 核心概念

### 为什么需要段页式？

| 方案 | 逻辑视角 | 物理视角 | 碎片 |
| --- | --- | --- | --- |
| 纯分段 | ✅ 面向用户：代码段、数据段、栈段各自独立 | ❌ 可变大小，外碎片 | 外部碎片 |
| 纯分页 | ❌ 对用户透明，一个地址空间 | ✅ 固定大小页框，无外碎片 | 内部碎片 |
| **段页式** | ✅ 分段（逻辑） | ✅ 分页（物理） | 仅内部碎片 |

### 地址转换流程（三级映射）

```
逻辑地址 = [段号, 段内偏移]
     ↓ 段表 (段号 → 段描述符: 基址 + 界限 + 页表指针)
线性地址 = [页号, 页内偏移]
     ↓ 页表 (页号 → 页框号)
物理地址 = 页框号 × 页大小 + 页内偏移
```

> 段内偏移的高位自动成为页号，低位成为页内偏移。硬件自动完成切割。

### Intel x86 内存模型（经典实例）

**实模式**：段寄存器 × 16 + 偏移 = 20 位物理地址（1MB 限制，无保护）

**保护模式**（段页式）：
1. **逻辑地址** = 16 位段选择子 (CS/DS/SS) + 32 位偏移
2. 段选择子查 GDT/LDT → 段描述符（基址 + 界限 + 属性 + DPL）
3. 基址 + 偏移 → **线性地址**（32 位）
4. 若分页未开启，线性地址即物理地址
5. 若分页开启：线性地址 → 页目录（10 位）→ 页表（10 位）→ 偏移（12 位）→ 32 位**物理地址**

**x86-64 (IA-32e)**：分段被弱化（基址强制为 0），分页升至 4 级（PML4→PDPT→PD→PT→Offset）

### 段表 + 页表 组合

- 每个进程一个**段表**（段数少，几项到几十项）
- 每段一个**页表**（该段内的分页索引）
- 优点：段与段之间互不干扰（各自独立的页表），段可独立换出
- 代价：两次查表（段表→页表）增加访问开销，TLB 不可或缺

### 段页式 vs 纯分页：实际选择

| 特性 | 段页式 | 纯分页 |
| --- | --- | --- |
| 用户可见逻辑结构 | ✅ 代码/数据/栈分开 | ❌ 平坦地址空间 |
| 内存碎片 | 仅内部碎片 | 仅内部碎片 |
| 共享与保护 | 更方便（按段设权限） | 需页级管理 |
| 表级数 | 二次查表 | 一次查表 |
| 主流采用 | 早期 Intel 保护模式 | **现代主流**（Linux/Windows 用平坦+分页） |

> 现代 OS 多采用「平坦模型 + 纯分页」：所有段的基址都设为 0，实际上只用分页。段的作用退化为权限控制。

## 易错点 / 高频考点

- [ ] 「段页式 = 分段的段表里存指向页表的指针」✅；「段页式 = 先分页后分段」❌
- [ ] 段页式下逻辑地址的段号来自指令或段寄存器隐含，不是从线性地址中切出的
- [ ] TLB 在段页式下更关键：缺一次访存= 段表+页表+数据 = 3 次访存，TLB 命中后仅 1 次

## 经典例题

**题干**：段页式下，逻辑地址由段号 S=1 和偏移 D=2500 构成。段表第 1 项指向的页表里，页号 2→框号 8。页大小 1KB。求物理地址。
**解答**：偏移 2500 = 2×1024+452，即页号=2、页内偏移=452。物理地址=8×1024+452=8192+452=8644=0x21C4。

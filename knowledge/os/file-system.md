## 一句话概括

文件系统管理**文件**（增删查改与逻辑结构）与**目录**（组织文件的索引），并把文件映射到磁盘的**物理存储**（分配方式）与**空闲空间管理**。

## 核心概念

### 文件逻辑结构

- 无结构文件：字节流（如 Linux 普通文件）
- 有结构文件：顺序文件（定长/变长）、索引文件、杂散文件（Hash）
- 顺序、索引、直接（随机）访问三种访问方式对比

### 文件物理分配方式

| 分配方式 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 连续分配 | 文件占连续磁盘块 | 顺序/随机访问都快 | 动态增长困难、外部碎片 |
| 链接分配 | 每块的下一块指针（链式） | 无外部碎片、易增删 | 只能顺序访问、指针占空间 |
| 索引分配 | 每个文件一个索引块，记录所有块地址 | 支持随机访问、易增删 | 索引块本身占空间 |

**重要**：文件块与页框同大小，文件系统存取以块为单位。磁盘空间分配与虚拟内存分页本质同构（块=页）。

### 目录结构

- 单级/两级/树形（最常用，可多级路径）/无环图（可共享）/图（有环，可链接）
- 目录项存：文件名 + 指向文件控制块的指针
- 文件控制块 FCB 即文件的「PCB」：存类型、大小、物理地址、权限、时间戳等

### inode（Linux/Unix 索引节点）—— 面试加分

- inode 存**除文件名外的文件全部元数据**（权限、大小、物理块指针…）+ 直接索引块 + 单重/双重/三重间接块
- 典型：12 个直接块 + 单间接 + 双间接 + 三间接 → 支持大文件且小文件开销小
- 删除文件=删除 inode（链接数减到 0）；`ls -i` 可看 inode 号

### 空闲空间管理

| 方法 | 说明 |
| --- | --- |
| 空闲链表 | 块级链，浪费指针空间、慢 |
| 位示图 Bitmap | 每一位表示一块空闲/占用，紧凑、可整块分配 |
| 成组链接法 | UNIX 采用，组内记录下一组空闲块，兼顾效率与规模 |

### 磁盘调度（常与文件系统同章考的并考点）

- FCFS / SSTF（短寻道优先）/ SCAN（电梯）/ C-SCAN / LOOK / C-LOOK
- 按**柱面号**计算寻道距离；电梯算法=单向扫描，可避免饥饿

## 易错点 / 高频考点

- [ ] 链接分配「不能随机访问」要用**索引分配**来实现随机访问
- [ ] 树形目录查找路径：自根到叶逐级，路径长度影响访问次数
- [ ] 软链接（符号链接）与硬链接：硬链接共享 inode，软链接是路径引用（跨文件系统可用软）
- [ ] 位示图计算：块号→字位偏移换算（第 i 文件块对应 bit 位置）

## 经典例题

**题干**：某文件系统 inode 含 12 个直接块指针、1 个单间接、1 个双间接、1 个三间接，每块 4KB，指针 4B。求最大单文件大小（约）。
**解答**：每块可存指针数 = 4KB/4B = 1024。直接 = 12×4K = 48K；单间接 = 1024×4K = 4M；双间接 = 1024×1024×4K = 4G；三间接 ≈ 4T。合计 ≈ 4T（主要来自三间接）。

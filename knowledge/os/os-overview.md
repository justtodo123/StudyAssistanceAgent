## 一句话概括

操作系统是管理硬件资源、提供程序运行环境的**系统软件**，向下高效管理资源，向上提供方便接口。理解 OS 体系结构与中断/系统调用是后续所有章节的基础。

## 核心概念

### 操作系统的定义与目标

- **资源管理者**：管理 CPU、内存、I/O 设备等硬件资源
- **扩展机器**：对裸机进行抽象，向用户/程序提供更方便的服务
- 核心目标：**方便性** + **有效性** + **可扩展性**

### OS 类型演进

| 类型 | 特点 | 典型 |
| --- | --- | --- |
| 手工操作 | 人机速度严重不匹配，CPU 大量空闲 | — |
| 单道批处理 | 引入监督程序，自动作业队列 | 早期 IBM |
| 多道批处理 | 内存中多道作业，CPU 与 I/O 并行 | IBM OS/360 |
| 分时系统 | 时间片轮转，交互式，多用户 | UNIX |
| 实时系统 | 确定性响应时间，硬实时/软实时 | VxWorks, RT-Linux |
| 现代 OS | 多模（批处理+分时+实时）融合 + 网络/分布式 | Windows, Linux |

### 内核体系结构（高频面试）

| 架构 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 单内核 (Monolithic) | 全部 OS 功能在内核态 | 性能好，调用无开销 | 庞大难维护，某模块崩溃→整个 OS 崩溃 |
| 微内核 (Microkernel) | 仅核心（IPC、调度、内存管理）在内核，其余在用户态 | 可靠、易扩展 | 频繁 IPC，性能开销大 |
| 混合内核 | 单内核 + 模块动态加载 | 折中性能和可靠 | Linux/Windows 主流 |
| 外核 (Exokernel) | 内核仅负责资源隔离与复用 | 极简 | 学术界 |

> Linux 是单内核+模块；Windows NT 是混合内核（带微内核基因）。

### 中断与异常（必考）

- **中断**（异步）：硬件信号通知事件完成（如 I/O 完成、时钟），与当前指令**无关**
- **异常**（同步）：指令执行中的错误（如除零、缺页），与当前指令**直接相关**
- **陷入 (Trap)**：程序主动请求 OS 服务（即系统调用）
- **中断向量表**：存放中断处理程序入口地址，硬件按中断号索引
- **中断处理流程**：保存现场 → 执行 ISR → 恢复现场 → 返回

### 系统调用 (System Call)

- 应用程序**请求 OS 内核服务**的唯一合法接口
- 与库函数的区别：系统调用**陷入内核态**执行，开销大；库函数大多在用户态
- 常见类别：进程控制 (fork/exit)、文件操作 (open/read/write)、设备、信息、通信

### 双重模式 (Dual Mode)

- **用户态**：不能执行特权指令（I/O、关中断、改页表基址寄存器等）
- **内核态**：可执行全部指令
- 切换：系统调用/中断/异常触发用户→内核；返回指令完成内核→用户
- 意义：保护 OS 不被破坏，强制资源访问控制

## 易错点 / 高频考点

- [ ] 「系统调用=库函数」❌ —— 库函数可能在内部调用系统调用，但不是同一概念
- [ ] 中断 vs 异常 vs 陷入：触发来源与是否同步要分清
- [ ] 分时系统 ≠ 实时系统：交互性 vs 确定性，常混淆
- [ ] 微内核「可靠」是因为模块隔离在用户态，以 IPC 性能为代价

## 经典例题

**题干**：简述从用户程序调用 `read()` 到数据返回的完整流程。
**解答**：用户程序调 `read()`（C 库）→ 库函数设置参数 → 执行 `syscall` 指令（陷入）→ 硬件切换内核态 → 中断向量表查系统调用处理入口 → 内核 sys_read() 执行（查文件描述符→读磁盘→拷到用户缓冲区）→ 返回用户态 → 库函数返回到程序。

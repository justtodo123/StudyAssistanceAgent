# M4 课程知识库规模补齐计划

> 版本：v1.0
> 制定日期：2026-08-18
> 当前状态：课程条目与评测补齐完成，测试通过，已于 2026-08-18 进入 `master`
> 适用范围：OS、DS、CO 三门核心课程知识库扩充

## 1. 背景与目标

M3 工程质量与沉淀已完成，但三门核心课程仍未达到项目长期标准：每门课程至少 20 篇知识条目。M4 专门补齐课程知识库规模，不修改 M3 已验收的平台功能。

| 课程 | 当前条目 | 目标 | 本阶段新增 |
| --- | ---: | ---: | ---: |
| OS | 15 | 20 | 5 |
| DS | 10 | 20 | 10 |
| CO | 10 | 20 | 10 |
| 合计 | 35 | 60 | 25 |

## 2. 阶段拆分

- **M4a：OS 扩充**：线程、IPC、实时调度、文件分配、设备管理。
- **M4b：DS 扩充**：分治、AVL/B 树、并查集、字符串匹配、哈希、图算法和外部排序。
- **M4c：CO 扩充**：数制编码、乘除法、Cache 映射、虚拟地址转换、控制器、流水线、总线与中断。
- **M4d：评测与文档收口**：更新导航、评测集、测试和项目状态。

## 3. 内容要求

每篇新增条目必须：

- 位于对应课程目录，使用 kebab-case 文件名；
- 包含 `title`、`course`、`tags`、`difficulty`、`updated` frontmatter；
- 包含 TL;DR、核心概念、关键原理、易错点、经典例题和关联条目；
- 使用 `docs/reference/{course}.md` 作为外部资料索引，不复制外部原始资料；
- 在课程 README 和 `knowledge/README.md` 中可导航、可统计。

## 4. 验收门禁

```text
M4 测试（14 项）→ M0_M2 基线 → regression 回归 → platform/tests → 三门 RAG 评测 → 文档检查 → 人工审查 → --no-ff 合并
```

验收要求：

- OS、DS、CO 各不少于 20 篇条目；
- 新条目 frontmatter 完整且导航链接有效；
- 评测集新增问题均引用实际知识文件；
- Recall@3 维持 `>= 0.8`；
- 不提交缓存、虚拟环境、模型文件或外部二进制资料。

本次验收结果：M4 测试 14 passed，根级测试 104 passed，平台测试 40 passed；离线 BM25 Recall@3：OS 1.000、DS 0.929、CO 1.000。

受限网络环境下，RAG 评测使用 `SA_USE_VECTOR=false` 验证 BM25 降级路径；向量模型缓存部署另行处理，不阻塞本阶段知识库扩充。
